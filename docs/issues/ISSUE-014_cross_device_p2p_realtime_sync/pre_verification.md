## Phase 19: PC（ローカル起動）↔ スマホ（クラウド起動）間のWebRTC P2Pリアルタイム同期と本番共有URL生成の修正 (Issue #14)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `BroadcastChannel` は同一ブラウザ内専用のため別端末・別オリジンに届かない。また `localhost:5173` ではスマホから開けない。 | 共有URL生成を `https://job-eval.pages.dev?sync=JE-XXXX` で固定。クロスネットワーク通信に WebRTC P2P / WebSocket リレーを導入。 |
| **2. UX・エッジケース** | スマホ側でURLを開いた際、またはルームコードを入力した際に、複雑な設定なしでワンタッチ接続できること。 | ルームコード（`JE-XXXX`）のみでシグナリングを行い、接続確立時に `smartMerge` で双方向の求人・プロファイルデータを即座に初期同期。 |
| **3. 永続性・互換性** | 外部サーバーに個人情報（求人・プロファイル）を永続化せず、Local-First 原則を厳格に保持すること。 | データは端末間の暗号化 P2P 通信および各端末の LocalStorage にのみ格納。サーバー保管ゼロ。 |
| **4. テスト容易性 & 自律性** | WebRTC / WebSocket モック環境でも確実に単体テストが完結し、`npm run check` が 100% PASS すること。 | `peerSync.test.ts` でメッセージ送受信および `smartMerge` 連動をテスト網羅。 |
