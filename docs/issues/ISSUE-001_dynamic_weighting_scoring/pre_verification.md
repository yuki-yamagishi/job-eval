## Phase 12: ユーザー志向に応じた4軸評価の動的重み付けカスタマイズ＆保存済求人の一括・リアルタイム再計算機能 (Issue #1)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | スコア再計算のたびに LLM API を呼び出すと通信遅延とトークン費用が発生するリスク。合計100%の整合性維持。 | 保存済みの各軸 0〜100% 生スコア（`scoreBreakdown`）を入力とする純粋関数 `recalculateScoreWithWeights` を実装し、0.01秒のゼロコスト決定論的再計算を実現。合計100%自動調整バランサーを導入。 |
| **2. UX・エッジケース** | 「リスキリング重視」「カルチャー重視」等のプリセットをワンクリックで切り替えたい。求人詳細やダッシュボードでの即時シミュレーション。 | プリセット選択ボタン（🎯標準 / 🚀リスキリング / 🌿カルチャー / 💰待遇 / ⚙️カスタム）を配置。プレビュー画面および一覧で視点切り替えピルを提供し、リアルタイムにスコア・判定ランク・ソート順を連動表示。 |
| **3. 永続性・互換性** | 重み設定（`scoringWeights`）の保存と、過去に作成されたプロファイル・求人データ（`JobAnalysisResult`）との後方互換性。 | `UserProfile.conditions.scoringWeights` にオプショナルとして定義し、未設定時はデフォルト（40/30/20/10%）を自動適用。「全求人に新しい重みを一括適用」ボタンで Markdown Frontmatter も安全に一括更新。 |
| **4. テスト容易性 & 自律性** | プリセットごとのスコア計算、合計100%バランサー、一括再計算、UI視点切り替えが Vitest で 100% 自律自動テスト可能か。 | `tests/core/scoringEngine.test.ts`, `tests/features/PreviewPane.test.tsx`, `tests/features/JobDashboard.test.tsx`, `tests/features/ProfileSettingsView.test.tsx` に単体・UIテストを追加。 |
