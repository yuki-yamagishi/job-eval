## Phase 14: スマートフォン向けレスポンシブUI最適化 & モバイル表示崩れの修正 (Issue #3)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | モバイル画面（幅320px〜480px）において、ヘッダーの長文テキストタブによる横溢れ、ルート要素の `overflow-hidden` による縦スクロール不能、テーブルのはみ出しが発生するリスク。 | Tailwind のブレークポイント（`md:`, `lg:`）を活用。ヘッダーはモバイルでアイコン表示＋ツールチップ/短縮ラベル化。メインコンテンツは `overflow-y-auto` を適切に配置し、テーブルには `overflow-x-auto` を付与。 |
| **2. UX・エッジケース** | スマートフォンでの片手操作時、タップ領域（44px以上）の確保と、入力フォーム（テキストエリア）と評価結果プレビューの切り替えやすさ。 | タブボタンの最小タップサイズを確保し、入力画面（InputPane）と評価結果（PreviewPane）がモバイルでも縦スクロールで自然に遷移・閲覧できるようにレイアウト調整。 |
| **3. 永続性・互換性** | UI レスポンシブ化に伴い、既存のデータモデル（`JobAnalysisResult`）やローカルストレージ・Markdown 保存の処理に悪影響を与えないこと。 | コアロジック（`src/core/`）およびストレージ層（`src/services/`）は一切変更せず、プレゼンテーション層（`src/components/`, `src/App.tsx`）のみを純粋にレスポンシブ化。 |
| **4. テスト容易性 & 自律性** | レスポンシブ化後も既存の 67 件の単体・UI テストがすべて PASS し、モバイル対応コンポーネントが Vitest / jsdom 環境で安全にレンダリング・動作検証可能か。 | 既存の UI テスト（`Header.test.tsx`, `JobDashboard.test.tsx`, `PreviewPane.test.tsx` 等）を維持し、`npm run check` の全テスト・ビルド検証を 100% 自動パスさせる。 |
