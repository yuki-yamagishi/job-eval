## Phase 15: クラウドデータベースによる複数デバイス間リアルタイムデータ同期の実装 (Issue #4, ADR-0006)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | クラウドDB接続時のレイテンシ、オフライン時の切断エラー、および外部SDK依存によるバンドルサイズ増加と初期化失敗リスク。 | Firestore `onSnapshot` によるネイティブリアルタイム購読を導入。未接続時や通信エラー時は自動的にローカルキャッシュおよび `LocalStorageAdapter` へ透過的フォールバックする防御設計。 |
| **2. UX・エッジケース** | 複雑なパスワード入力や認証なしで、PCとスマホを素早くペアリングできること。同期状態（同期中/オフライン/未設定）がUI上で一目でわかること。 | 「同期ルームID / 6桁ペアリングコード」方式を採用し、ワンクリックでQRコード表示・スマホ側で読み取り可能にする。ヘッダーに「🟢 クラウド同期中」「☁️ ローカル動作」のインジケーターを常設。 |
| **3. 永続性・互換性** | 既存の `JobAnalysisResult` および `UserProfile` データ構造を100%維持し、ローカルMarkdownエクスポートや既存データとの完全互換性を確保。 | `StorageAdapter` インターフェースに `subscribeJobs` / `subscribeProfile` / `setSyncRoom` などの購読メソッドを安全に拡張し、純粋なコアビジネスロジック（`src/core/`）には一切手を加えない。 |
| **4. テスト容易性 & 自律性** | 外部クラウドAPI（Firebase）に依存するテストがCIやローカル環境で失敗・ブロックされないこと。 | `MockStorageAdapter` / `InMemoryStorageAdapter` による自律テスト環境を提供し、`npm run check` の全テスト（13ファイル67件以上）がモック環境下で完全オフライン自律動作することを保証。 |
