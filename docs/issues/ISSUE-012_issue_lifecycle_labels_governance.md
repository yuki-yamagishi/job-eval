# [Issue] AGENTS.md における Issue ライフサイクル管理規定（Backlog / To Do / Ready / In Progress / Done）とエージェント自律判断ルールの明文化

- **ステータス**: 🔵 着手可能 (Ready / To Do)
- **優先度**: 高 (High)
- **カテゴリ**: 開発ハーネス, ガバナンス, CI/CD
- **対象プラットフォーム**: 全プラットフォーム

---

## 📌 課題の概要 (Problem Description)

現在の `AGENTS.md` には、Issue のステータス（`backlog` vs `ready` vs `in-progress`）に応じた AI エージェントの自律着手可否の明確な判断基準が記載されていなかった。
そのため、エージェントが自律動作する際に「バックログとしてストックされたタスクを誤って開発開始してしまう」ことや、「どのIssueが開発着手可能か判別できない」リスクが存在した。

本 Issue では、アジャイル標準に基づく Issue ライフサイクルと、AI エージェントの行動プロトコルを `AGENTS.md` に明文化してガバナンスを確立する。

---

## 🎯 要件定義 (Requirements)

### 1. Issue ライフサイクルとラベルの定義
| ステータス / ラベル | 意味・状態 | エージェントの行動基準 |
| :--- | :--- | :--- |
| **🟡 `backlog`** | アイデア・要望の保管。今すぐ着手しない。 | **着手禁止**。ユーザーの明示指示まで待機。 |
| **🟠 `todo`** | 直近の実施候補。要件詳細化中。 | 要件・設計の整理を優先。 |
| **🔵 `ready`** | 要件定義・受入基準・設計が確定し、着手準備完了（DoR達成）。 | **自律的に開発開始可能**。 |
| **🟣 `in-progress`** | トピックブランチを作成し、実装・テスト作業中。 | 開発実行。 |
| **🟢 `done`** | PRマージ＆品質ゲート合格完了。 | Issue 自動クローズ。 |

### 2. エージェントの自律着手プロトコル
- エージェントは `ready` ラベルの Issue、またはユーザーが明示的に指定した Issue のみ着手する。
- 着手時はラベルを `in-progress` に更新し、トピックブランチを作成する。
- `backlog` ラベルが付いている Issue は、指示がない限り勝手に実装を進めてはならない。
