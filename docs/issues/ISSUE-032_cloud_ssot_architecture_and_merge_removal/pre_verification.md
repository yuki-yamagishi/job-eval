## Phase 29: クラウド SSoT アーキテクチャ刷新とマージ機能全廃 (Issue #32)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `smartMerge` による中途半端な分散マージが原因で初期プロファイルや削除求人が混ざり合って崩壊する問題。 | Cloudflare D1 を SSoT（唯一の正本）と定め、マージを全廃して完全スナップショット同期（上書き・ミラーリング）に一本化。 |
| **2. UX・エッジケース** | デプロイや新端末アクセス時に初期値（山田 太郎）が最新判定されてクラウドを上書きするリスク。 | `DEFAULT_USER_PROFILE.updatedAt` を最古値 `1970-01-01` に固定。ルーム接続時はクラウド実データで初期値を無条件破棄・置換。 |
| **3. 永続性・互換性** | 端末側で求人を削除しても D1 から行が消えず、他端末で復活するバグ。 | `functions/api/sync.ts` の PUSH 処理で、送信リストに含まれない旧求人を一括 DELETE（スナップショット整合性確保）。 |
| **4. テスト容易性 & 自律性** | WebSocket の大容量生データ送信による通信エラー。 | WebSocket は軽量シグナル `{ type: "DATA_UPDATED", roomId }` のみに限定し、データ本体取得は D1 Pull に統一。テストもスナップショット仕様に刷新。 |
