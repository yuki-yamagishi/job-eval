## Phase 25: プロファイル設定変更中の同期リセット防止、スマホ向け常時固定保存バー導入、および同期のシンプル化 (Issue #26)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `ProfileSettingsView` の `useEffect` がバックグラウンド同期で発火し、編集中 `draft` を上書きしていた。 | `isDirty` ステートを導入し、編集中は外部からの `profile` 更新通知によるドラフト自動上書きを完全ブロック。 |
| **2. UX・エッジケース** | スマホで下までスクロールして編集した後に上まで戻るのが著しく苦痛。 | `fixed bottom-0` の Sticky Bottom Action Bar を配備し、未保存通知と「保存する」ボタンを常時アクセス可能に配置。 |
| **3. 永続性・互換性** | プロファイルの「スマートマージ」を廃止し、保存されたデータをそのままクラウドD1へ反映する設計へシンプル化。 | 複雑なマージを完全排除し、最新の編集データをそのままローカル＆クラウドD1の正として保存・取得。 |
| **4. テスト容易性 & 自律性** | `ProfileSettingsView.test.tsx`、`smartMerge.test.ts` を含む全テストが 100% PASS すること。 | 保存ボタンの既存ロール・テキストを維持し、固定バーとヘッダーの両方で動作を保証。 |
