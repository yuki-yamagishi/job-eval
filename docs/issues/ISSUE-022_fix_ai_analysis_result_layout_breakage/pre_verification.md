## Phase 23: AI解析後プレビュー画面（PreviewPane）における表示レイアウト崩れの修正 (Issue #22)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | 2ペイン表示時（幅600px〜800px）やモバイル画面において、ヘッダーアクションやグリッドが固定幅で衝突する。 | `PreviewPane.tsx` のヘッダーを `min-h-12 py-2 flex flex-wrap` にし、グリッド（スコア内訳・ポジティブ/懸念点）をレスポンシブ化。 |
| **2. UX・エッジケース** | 企業名・求人タイトルが長い場合でもスコア表示や各ボタングループが綺麗に収まり、操作性を損なわないこと。 | タイトルとスコアの横並びをフレックスラップ化し、文字サイズと余白を最適化。 |
| **3. 永続性・互換性** | レイアウト改修による状態管理やイベントハンドラ（保存、再評価、コピー、スプリット編集）への影響ゼロ。 | 既存の props、ステート、コールバック構造は 100% 維持。 |
| **4. テスト容易性 & 自律性** | `PreviewPane.test.tsx` を含む全テストが 100% PASS すること。 | 既存のボタン要素名・テキスト・ロールを変更せず維持し、テストの回帰を防止。 |
