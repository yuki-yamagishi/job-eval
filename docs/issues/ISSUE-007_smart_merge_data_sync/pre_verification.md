## Phase 16: 求人・プロファイルデータのスマートマージとコンフリクト解消 (Issue #7, ADR-0007)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | PC[A, C] と スマホ[A, B] で求人Aのステータスが「書類選考」と「一次面接」で異なる場合、どちらを正とするかの競合（コンフリクト）。 | Last-Write-Wins (LWW) 原則を採用し、`metadata.updatedAt` または `analysisDate` の新しい方を採用。差分履歴（`evaluationHistory`）も重複排除マージ。 |
| **2. UX・エッジケース** | ユーザーがPCとスマホのどちらから同期を開始しても、操作中の求人が消えたり巻き戻ったりせず、全求人（A, B, C）が自動統合されること。 | `mergeJobs` と `mergeProfile` による和集合自動マージをストレージ受信時に透過的に実行。ユーザーへの特別な確認ダイアログや警告なしに完全自動解決。 |
| **3. 永続性・互換性** | マージ処理後の求人データがローカルストレージおよび Markdown 構造と 100% 整合し、データ破損が起きないこと。 | `JobAnalysisResult` および `UserProfile` の型定義に完全準拠した純粋関数として実装し、各フィールドの欠落を防止。 |
| **4. テスト容易性 & 自律性** | エッジケース（空配列、完全重複、完全差分、タイムスタンプ逆転、プロファイルスキル合体）が Vitest で 100% 単体テスト可能か。 | `tests/core/smartMerge.test.ts` を作成し、純粋関数の全ケースを網羅的に自動テスト。 |
