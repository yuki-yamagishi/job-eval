# Issue #60: 自己修復ループの信頼性向上（バッククォート接頭辞パース、npm.cmdウォッチ防止、Fleet権限整合、緊急脱出案内）

## 1. 開発の背景と目的 (Context & Purpose)
ADR-0016 によるループエンジニアリングハーネスの配備および Issue #56 の Stop Hook デッドロック防止対策を経て、自己修復ループ基盤が確立されました。
しかし、実際の自律実行において重大な指摘の見落とし（バッククォート囲み接頭辞のスキップ）、対話型コマンド（`npm.cmd test`）のすり抜け、PR番号の誤認（Issue番号混同）、Fleet実行権限のギャップなどの潜在リスクが確認されました。
本 Issue ではこれらの課題を一括解決し、ガードレール付き自己修復ループの完全性と信頼性を向上させます。

## 2. 要件定義 (Requirements)
1. **`parseReviewResult.js` におけるバッククォート囲み接頭辞パース**:
   - ``- `[must]`: ○○`` や ``* **`[should]`**: ○○`` などバッククォートで装飾された接頭辞を正規表現で確実に抽出。
   - `line.includes('`[must]`')` 等による無差別スキップ判定を廃止し、凡例行の誤判定・本番指摘の読み飛ばしを根絶。
2. **`preToolHook.js` における `npm.cmd` 対話型テストの拒否**:
   - ウォッチモード拒否の正規表現を `/\bnpm(?:\.cmd)?\s+(?:run\s+)?test\b/i` に拡張し、Windows 環境でのハングを防止。
3. **`postToolHook.js` における PR 番号解決の安全性向上**:
   - コマンドラインからの Issue 番号抽出（`closes #46` 等）による PR 番号誤認フォールバックを排除。
4. **`stopHook.js` / `loopState.js` における緊急脱出プロトコル案内**:
   - 停止拒否メッセージに「ユーザー指示による中断時や異常時は `node scripts/harness/loopState.js reset` を実行して状態を初期化してください」という明確なエスケープハッチを明記。
5. **Fleet レビュアーの最小権限と実行責務の整合化**:
   - Fleet サブエージェントは最小権限（コード検査＆Markdown 出力）に特化し、PR スレッドへの公式投稿および loopState 更新は親エージェントが安全に一括実行する責務分担に規約・プロンプトを統一。

## 3. 受け入れ基準 (Acceptance Criteria)
- [ ] バッククォート囲み（``- `[must]`: ...``）のレビュー指摘が正しく `must` / `blocking` として抽出されること。
- [ ] `npm.cmd test` のコマンドが `preToolHook` で確実に拒否されること。
- [ ] `stopHook` の拒否メッセージに `loopState.js reset` のエスケープ案内が含まれること。
- [ ] `tests/harness/` 配下の単体テストが拡充され、全件合格すること。
- [ ] `npm.cmd run check` が 100% パスすること。
