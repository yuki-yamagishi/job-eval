# [Refactor/Feature] クラウド SSoT アーキテクチャ刷新とマージ機能全廃

- **ステータス**: ✅ 完了 (Closed / Merged via PR #33)
- **優先度**: 高 (High / Critical)
- **カテゴリ**: クラウドDB, D1, E2EE, SSoT, スナップショット同期, データ整合性, リファクタリング
- **対象プラットフォーム**: 全プラットフォーム (Web / Mobile / Desktop)

---

## 📌 課題の概要 (Problem Description)

これまで「差分最小化」として機能追加を重ねた結果、同一ユーザーによる端末間データ共有・引き継ぎという用途に対して過剰な「分散マージ（`smartMerge`）」が存在していた。
これにより、以下の深刻な構造的矛盾が発生していた：

1. **初期プロファイルによるクラウドデータの上書き破壊**:
   - `DEFAULT_USER_PROFILE.updatedAt` にアクセス時の現在時刻が入る仕様だったため、新しいURLやデプロイ直後にアクセスした端末のサンプル初期値（山田 太郎）が「最新データ」と判定され、クラウド上のユーザー実データを上書き・破壊してしまっていた。
2. **削除求人のゾンビ復活**:
   - D1 API (`/api/sync`) が差分 Upsert のみで削除に対応していなかったため、端末側で求人を削除しても D1 にレコードが残り、別端末で開いた際に削除した求人が復活していた。
3. **不要な分散マージの複雑性とゾンビ増殖**:
   - 複数人同時タイピングではない単一ユーザーの端末間同期において、配列マージや LWW 比較を行うことで、古いデータや初期値が混ざり合い整合性が崩壊していた。
4. **WebSocket リレーの肥大化と不安定性**:
   - 外部無料サービス（`ntfy.sh`）経由で大容量の求人・プロファイル実データを送信しようとし、4KB超えのパケットで不安定になっていた。

## 🎯 要件定義 (Requirements)

### 1. クラウド SSoT（Single Source of Truth: 唯一の正本）の確立
- **Cloudflare D1 を唯一の正本** と定義する。
- 端末が同期ルームに接続した際、クラウドにデータが存在する場合は **ローカルの初期ダミー値（山田 太郎 等）を破棄し、クラウドのデータをそのまま展開（上書き）** する。
- クラウドが空（新規ルーム作成時）の場合のみ、ローカルのデータをクラウドへ初保存する。

### 2. マージ機能（`smartMerge.ts`）の全廃とスナップショット同期化
- 配列の結合や LWW フィールドマージロジックを全廃。
- 保存時は「現在の端末の有効データ（スナップショット）」をそのままクラウドへ PUSH し、取得時はクラウドのスナップショットをそのままローカルへ反映する。

### 3. D1 API (`/api/sync`) の削除対応・完全スナップショット整合性
- PUSH 時に求人リストを受信した場合、そのリストに含まれない旧求人レコードを D1 上で一括削除（`DELETE FROM sync_jobs WHERE room_id = ? AND job_id NOT IN (...)`）し、ローカルで削除された求人がクラウドからも完全に消去されるようにする。

### 4. `DEFAULT_USER_PROFILE` のタイムスタンプ汚染防止
- `DEFAULT_USER_PROFILE.updatedAt` を過去固定値（`"1970-01-01T00:00:00.000Z"`）に変更し、クラウドデータを決して上書きしないようにする。

### 5. WebSocket 通信の軽量シグナル（Ping）化
- WebSocket（ntfy.sh）による生データ送信を廃止。
- 送信するのは `{ type: "DATA_UPDATED", roomId }` という軽量シグナルのみとし、受信端末は D1 から最新スナップショットを Pull する構成に統一する。
