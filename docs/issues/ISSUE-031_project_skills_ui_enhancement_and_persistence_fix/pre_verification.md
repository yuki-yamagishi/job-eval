## Phase 28: プロジェクト使用技術・スキルスタックの保存消失バグ修正 ＆ 資格・スキル設定準拠UI刷新 (Issue #31)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `projectSkillInput` の未コミット文字列が「保存」ボタン押下時に破棄される根本原因。 | `handleSaveProjectModal` 実行時に `projectSkillInput` が残っていれば、カンマ分割して自動的に `skills` にマージしてから親に渡す自動ガードを実装。 |
| **2. UX・エッジケース** | スマホ環境で Enter キーが押しづらい、資格UIのような明確な追加ボタンがない。 | プロファイル設定の資格UIに準拠し、バッジ一覧表示エリア＋独立した「追加」ボタン＋カンマ区切り一括登録＋保有スキルからの候補チップ選択を提供。 |
| **3. 永続性・互換性** | 文字列配列（`string[]`）としてのデータ整合性。 | 重複排除（trim & unique）を実施し、既存の D1 暗号化同期パイプラインと完全互換。 |
| **4. テスト容易性 & 自律性** | 未確定テキストがある状態での保存、および「＋追加」ボタンのクリック動作検証。 | `CareerHistoryView.test.tsx` に「未確定テキストがある状態で保存した際にスキルが保存されること」「追加ボタンでスキルが追加されること」のテストを追加。 |
