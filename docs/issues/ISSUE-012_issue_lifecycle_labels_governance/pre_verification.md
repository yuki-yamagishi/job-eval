## Phase 18: AGENTS.md における Issue ライフサイクル管理規定とエージェント自律判断ルールの明文化 (Issue #12)

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | GitHub の Issue ラベル（`backlog`, `todo`, `ready`, `in-progress`, `done`）とローカルドキュメントメタデータが矛盾なく整合すること。 | 各ステータスの定義、カラー、エージェントの行動基準（着手可否判定）をマトリクス形式で `AGENTS.md` に明文化。 |
| **2. UX・エッジケース** | AI エージェントが勝手にバックログ（`backlog`）のタスクを開発開始してしまう事故を確実に防止すること。 | 「`backlog` ラベルが付いている Issue はユーザーからの明示的な着手指示がない限りスキップする」という厳格なガードレールを定義。 |
| **3. 永続性・互換性** | 既存のアーキテクチャ規約、ADR運用ルール、品質検査スクリプトとの完全な整合性を維持すること。 | 既存の「第2章: AIアシスト Issue & PR + ADR ハイブリッド開発フロー」を自然に拡張・体系化。 |
| **4. テスト容易性 & 自律性** | ドキュメント更新後も `scripts/docCheck.js` および `npm run check` の全テスト・ビルドが 100% PASS すること。 | `npm run check` を実行し、全ゲートの完全合格を自律検証。 |
