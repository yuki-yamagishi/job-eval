# [Feature] プロジェクト実績の解像度向上: 担当開発工程（フェーズ）選択機能 ＆ 1プロジェクト内複数STARエピソード管理の実装

- **ステータス**: 🔵 着手可能 (`status: ready`)
- **優先度**: 高 (High / Profile & Career Enhancement)
- **カテゴリ**: `type: feature`, 職務経歴, STAR法, 開発工程, AI評価連携, UI/UX
- **対象プラットフォーム**: 全プラットフォーム (Web / Mobile / Desktop)

---

## 📌 課題の概要 (Problem Description)

現在の職務経歴機能では、プロジェクトごとに登録できる STAR（状況・行動・成果）が 1 組に固定されており、1 つのプロジェクト（半年〜数年規模）で複数の異なる成果・課題解決（例: DB負荷改善、CI/CD自動化、若手育成等）を達成した際に、成果を分けて記載できない制約がある。
また、日本のIT転職市場においてスキルレベルや年収レンジの判定基準として極めて重視される **「担当システム開発工程（要件定義、基本設計、詳細設計、実装、テスト、運用保守、PMなど）」** を選択・記録する機能が不足している。

---

## 🎯 要件定義 (Requirements)

### 1. 担当システム開発工程（フェーズ）選択機能
- プロジェクト編集モーダルにおいて、以下の代表的な開発工程をワンタップで複数選択できるバッジ/チェックボックス群を提供：
  - `要件定義` `基本設計 / アーキテクチャ` `詳細設計` `実装・コーディング` `テスト・QA` `リリース・CI/CD` `運用・保守` `PM / 進捗管理`
- 任意のカスタム工程もテキスト追加可能。
- 職務経歴書（Markdown）出力に「- **担当工程**: 要件定義, 基本設計, 実装, 運用・保守」として反映。
- 求人AI解析プロンプトに担当工程を注入し、「要件定義からリードできるエンジニア」等の求人要件との適合度判定を強化。

### 2. 1プロジェクト内での複数STARエピソード管理機能
- 1つのプロジェクトに対して、「＋ 実績エピソード(STAR)を追加」ボタンで複数の STAR カード（テーマ、課題、工夫・行動、成果）を追加・削除・編集可能にする。
- 各エピソードごとに個別の「✨ AI文章整形」を実行可能。
- 職務経歴書（Markdown）出力に、プロジェクト内の全エピソードを構造化して出力。
- 求人AI解析プロンプトへ全エピソードの情報を注入。

### 3. データ後方互換性の保証
- 既存の単一 `situation`, `action`, `result` を持つデータも壊れることなく、自動的に最初の `starEpisodes` として表示・マイグレーションされる設計。
