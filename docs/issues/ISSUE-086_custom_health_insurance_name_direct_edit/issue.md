# Issue #86 仕様書: 会社独自健保（単一健保等）の実名抽出・表示および直接編集の実装と不要な大分類フィルターの全廃

## 1. 解決すべき課題・背景 (Why & Background)
Issue #80 で導入された福利厚生（健康保険）機能は、「ITS健保」「TJK健保」「協会けんぽ」などの固定カテゴリーへの丸め込みを前提として設計されていました。
しかし、日本には大企業やメガベンチャーが独自に設立する「単一健康保険組合」が約1,380組合存在し、それぞれ独自の保険料率や手厚い福利厚生（直営保養所、付加給付、人間ドック補助等）を提供しています。

現状の実装では、これらの会社独自健保が「自社・単一健保」「その他健保」という抽象的なカテゴリーに強制的に丸められてしまい、**「実在する会社独自の健保名（例: サイバーエージェント健康保険組合、日立健康保険組合 等）が表示・保存できない」** という重大な課題が生じています。
また、ユーザーが手動で健保名を設定しようとしても固定のドロップダウンしかなく、自由な実名を入力する手段がありません。
さらに、求人一覧画面の「全健保」ドロップダウンフィルターは、求人絞り込みのニーズに合致しない過剰設計であり、検索バーのフリーワード検索で代替できるため全廃すべきです。

したがって、不要な大分類カテゴリーへの丸め込みと専用フィルターを撤廃し、**「Web調査・求人票から実在する健保名をありのまま取得・表示し、ユーザーが実名を直接テキスト入力・編集できるシンプルな実名制アーキテクチャ」** へ刷新します。

---

## 2. 現状の根本原因 (Problem Statement)
1. **大分類 Enum への丸め込み**:
   - `inferHealthInsuranceType` が会社独自の健保を `corporate` や `other` に一括分類し、実名ではなく大括りの固定ラベル（「自社・グループ単一健康保険組合」等）を表示してしまう。
2. **手動入力欄の欠如**:
   - `PreviewPane` の手動変更が固定ドロップダウン（ITS, TJK, 協会けんぽ, 自社健保, その他）のみとなっており、健保の正式名称をテキスト入力して保存する input が存在しない。
3. **不要な大分類フィルターによるUI圧迫**:
   - `JobDashboard` に「全健保」ドロップダウンが存在するが、健保ごとの絞り込みニーズは低く、キーワード検索窓で十分に代替可能である。

---

## 3. 排除するリスク (Risks to Eliminate)
- **独自健保の実名消失リスクの排除**: 大企業・IT企業の独自健保名が「自社健保」などの抽象ラベルに消されることなく、実名で画面・Markdownに保持されること。
- **既存求人データのパース破壊リスクの排除**: 既存の `benefitResearch` データや旧形式の求人データが型エラーや表示崩れを起こさないこと。
- **AI による健保名の捏造（ハルシネーション）防止**: Web検索ツール（Google Search Grounding）を活用し、推測ではなく公開情報に基づいた確度付きで実名を抽出すること。

---

## 4. 変更方針 & 実装スコープ (Proposed Changes)
1. **Web調査プロンプト・抽出ロジックの改善**:
   - Gemini プロンプトにおいて、固定カテゴリーへの丸め込みを廃止し、企業の実際の健康保険組合名（例: `〇〇健康保険組合`, `全国健康保険協会 〇〇支部`）を忠実に抽出するよう指示。
   - 求人票本文からの抽出ロジック（`extractHealthInsuranceFromText`）でも、「〇〇健康保険組合」の実名パターンをそのまま抽出。
2. **PreviewPane（詳細画面）の実名化と直接編集**:
   - 「自社・グループ単一健保」等の固定ラベルをやめ、実名（`healthInsurance.name`）を主役に表示。
   - **健保名の自由テキスト入力・編集欄**（インライン編集または入力フォーム）を提供し、ユーザーが実名を自由に入力・保存できるようにする。
   - ITS / TJK / 協会けんぽ等の代表的健保はワンクリック入力チップとして支援。
3. **JobDashboard（一覧画面）の実名バッジ・フリーワード検索統合と不要フィルター全廃**:
   - 求人カード上のバッジを、固定ラベルではなく実名（例: `[サイバーエージェント健保]`, `[ITS健保]`, `[協会けんぽ]`）で表示。長大な正式名称に対する短縮ユーティリティ（`getHealthInsuranceBadgeLabel`）によりレイアウト崩壊を防止。
   - 上部フィルターバーの「全健保」ドロップダウンを削除し、**フリーワード検索（`matchesQuery`）の検索対象に健保名（`benefitResearch.healthInsurance.name`）を追加統合**。

## 5. 受け入れ基準 & 完了定義 (Acceptance Criteria / DoD)

### 5.1. 機能受け入れシナリオ (Given-When-Then)

- **シナリオ 1: Web調査による会社独自健保の実名取得と表示**
  - **Given**: 自社健保を持つ企業（例: サイバーエージェント、日立等）の求人を対象にWeb調査を実行する。
  - **When**: Gemini が Google 検索を通じて調査を行う。
  - **Then**: 抽象的な「自社健保」ではなく、「サイバーエージェント健康保険組合」などの実名と具体的なメリットが `healthInsurance.name` に抽出され、画面に明示されること。
- **シナリオ 2: 求人票本文からの会社独自健保名の実名直接抽出**
  - **Given**: 求人票本文に「〇〇健康保険組合加入」と明記されている。
  - **When**: 求人解析（Track 1）を実行する。
  - **Then**: 「その他健保」等に丸められず、「〇〇健康保険組合」が抽出・表示されること。
- **シナリオ 3: PreviewPane での健保名テキスト直接入力・編集と空文字バリデーション**
  - **Given**: 詳細画面（PreviewPane）で求人を表示している。
  - **When**: 健保名入力欄に「〇〇健保」と手動入力して保存する。また、入力欄を全消去（空文字または空白のみ）して保存を試みる。
  - **Then**: 有効な健保名を入力した場合は即座に反映・ローカル保存され、Markdown にも反映されること。空文字または空白のみの場合は保存が抑止されて直前の値が維持されるか、あるいは「健保未確認」として安全にリセットされ、空バッジ `[ ]` の生成や Markdown 出力の破損を物理防止すること。
- **シナリオ 4: JobDashboard での健保実名バッジ表示・長大名レイアウト保護・不要フィルター全廃**
  - **Given**: 健保名が設定された求人が一覧画面に表示されている。
  - **When**: 求人カードおよび上部フィルターバーを確認する。
  - **Then**: カード上に実名ベースのバッジ（例: `[〇〇健保]`）が表示され、不要な「全健保」ドロップダウンが削除されていること。20文字以上の長大名称が登録されている場合でも、短縮表示（`getHealthInsuranceBadgeLabel`）または truncate ＋ title 属性による正式名ツールチップにより、カードおよびテーブルのレイアウト崩れが防止されること。
- **シナリオ 5: フリーワード検索（searchQuery）での健保名ヒット**
  - **Given**: 社名・求人タイトル・タグには健保名文字列を含まないが、健保名として「関東ITソフトウェア健康保険組合 (ITS健保)」または「サイバーエージェント健康保険組合」が登録された求人が存在する。
  - **When**: 一覧画面の検索バーに「ITS」または「サイバーエージェント」と入力する。
  - **Then**: `matchesQuery` の判定により当該求人が正確にヒットして絞り込まれること。
- **シナリオ 6: 既存データ（旧データ）の後方互換性**
  - **Given**: `its`, `tjk`, `corporate`, `other` などの旧形式データ、または健保未調査の既存求人が読み込まれる。
  - **When**: 一覧画面や詳細画面を表示する。
  - **Then**: エラーなく正常にフォールバック表示されること。
