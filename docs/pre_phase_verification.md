# Pre-Phase Verification Report (事前検証レポート)

各フェーズ着手前に実施する 4 軸（技術環境、UX、データ永続性、テスト自律性）の事前検証ログです。

---

## Phase 4: Markdown生成 & リッチプレビュー & Vault保存

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Frontmatter (YAML) を react-markdown で綺麗に表示・分離する必要性。 | `remark-frontmatter` を適用し、YAML と Markdown 本文を視覚的に整理してレンダリング。 |
| **2. UX・エッジケース** | 企業名・職種に OS 禁止文字 (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`) が含まれるリスク。 | `getStandardMarkdownFilename` で厳格サニタイズを実施し、不正ファイル名による保存失敗を防止。 |
| **3. 永続性・互換性** | Obsidian, Logseq 等の Vault 直下に直接保存した際、タグやプロパティが即座に認識される互換性。 | 標準 YAML Frontmatter（配列タグ・日付）書式に厳密準拠。 |
| **4. テスト容易性 & 自律性** | エディタ双方向編集やファイル書き出しが自動テスト可能か。 | サニタイズ・パースの単体テストおよびエディタUIテストを Vitest で 100% ローカル完結。 |
