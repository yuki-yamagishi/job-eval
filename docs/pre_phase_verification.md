| **4. テスト容易性 & 自律性** | 再生成トリガー、UI ローディング挙動、専用プロンプトのテストが Vitest で自律実行可能か。 | `tests/features/PreviewPane.test.tsx` に再生成ボタンの押下・コールバック呼び出しテストを追加。 |

## Phase 8: 中長期キャリア展望・獲得スキル・次の転職先 (Career Trajectory) AI & 可視化

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Gemini API のプロンプトおよび JSON Schema への `career_trajectory` オブジェクト追加と推論遅延の抑制。 | `career_trajectory` (獲得スキル, 次のキャリア選択肢, 将来想定年収, キャリア留意点) を Gemini JSON Schema に定義。既存の高速 Flash モデル（3.6/3.5）で数秒以内に安定生成。 |
| **2. UX・エッジケース** | 「入社後のキャリアの広がり」が視覚的にわかりやすく、単なる転職判断だけでなく 3〜5 年のキャリア戦略ツールとして機能すること。 | プレビュー画面に「🚀 入社後のキャリア展望 & 次の転職先」リッチカードを配置。ロードマップ画面にも「キャリア分岐 & 将来年収シミュレーション」を連動。 |
| **3. 永続性・互換性** | 過去に保存・インポートされた求人データに `careerTrajectory` が存在しない場合のフォールバック。 | `careerTrajectory?: CareerTrajectory`（オプショナル）として定義し、既存データとの完全な後方互換性を保証。Markdown にも専用セクションを自動生成。 |
| **4. テスト容易性 & 自律性** | `MockAiProvider` でのキャリア展望シミュレーション生成、および UI 表示の自動テスト化。 | `MockAiProvider` に業種・職種・年収に応じたキャリアパス生成ロジックを実装し、Vitest で 100% 自律単体テストを担保。 |

## Phase 7: 自動ローカル保存・再表示・AI再評価・MDインポート・横並び比較 & 転職ロードマップ画面

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Markdown (`.md`) インポート時の YAML Frontmatter パースと、AIへのフィードバック付き再評価プロンプトの設計。 | 既存の `parseJobMarkdown` を拡張してドラッグ＆ドロップ/ファイル選択に対応。AI 再評価用プロンプトビルダー（前回評価＋ユーザーフィードバック）を新設。 |
| **2. UX・エッジケース** | 解析完了時に手動保存を押さなくても自動でローカル保存される安心感。保存済み案件のワンクリック再表示。複数案件の横並び比較。選考状況（応募検討中/面接/見送り等）と不足資格を俯瞰するロードマップ画面。 | ① 解析完了時の自動ローカルストレージ保存（ドラフト同期）、② ダッシュボードからの1クリック再プレビュー復元、③ プレビューペイン内の「💡 フィードバックして再評価」フォーム、④ ドキュメントインポートモーダル、⑤ 横並び比較マトリクス、⑥ 新ナビゲーション「ロードマップ」タブの新設。 |
| **3. 永続性・互換性** | ユーザーフィードバック履歴や更新日時が Markdown Frontmatter およびローカルストレージの両方で正しく永続化されること。 | `JobAnalysisResult` に `feedbackHistory?: Array<{ date: string; feedback: string; scoreDelta: number }>` を追加し、既存データとの完全互換を維持。 |
| **4. テスト容易性 & 自律性** | Markdown インポート、AI 再評価ロジック、ロードマップ集計ロジックが、APIキーなしのローカル環境でも 100% 単体テスト可能か。 | `MockAiProvider` に再評価ロジックを組み込み、Vitest でインポートパース・フィードバック再評価・ロードマップ集計を 100% 自動テスト化。 |

## Phase 6: スキル・資格ステータス管理 & 資格推薦AI & 状態同期・接続テスト

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `ProfileSettingsView` でのプロファイル保存が `App.tsx` に即時反映されず `Mock モード` のままになる状態管理の不整合。 | `App.tsx` から `profile` および `saveProfile` を `ProfileSettingsView` に渡し、メモリ上の状態とストレージを単一ソースで同期。 |
| **2. UX・エッジケース** | APIキーが正しいか保存前に確認できない不安、資格・スキルの「取得済」と「学習中・目標」の混同。 | Gemini API 接続テストボタン（疎通確認）を新設。資格・スキルにステータス（取得済/学習中/目標）を追加し、タブ切り替えUIで直感的に登録。 |
| **3. 永続性・互換性** | 資格・スキル構造の拡張に伴う既存プロファイル（LocalStorage/Tauri FS）の後方互換性。 | 既存データに `status` がない場合はデフォルト値（`acquired` / `experienced`）を自動補完しマイグレーション。Markdown Frontmatter にも推奨資格プロパティを互換拡張。 |
| **4. テスト容易性 & 自律性** | API接続テストや資格アドバイス抽出ロジックが、APIキーなしのローカル環境でも 100% 単体テスト可能か。 | `MockAiProvider` にも `qualificationAdvice` モック生成を実装し、Vitest で完全ローカル自律テストを保証。 |

## Phase 4: Markdown生成 & リッチプレビュー & Vault保存

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Frontmatter (YAML) を react-markdown で綺麗に表示・分離する必要性。 | `remark-frontmatter` を適用し、YAML と Markdown 本文を視覚的に整理してレンダリング。 |
| **2. UX・エッジケース** | 企業名・職種に OS 禁止文字 (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`) が含まれるリスク。 | `getStandardMarkdownFilename` で厳格サニタイズを実施し、不正ファイル名による保存失敗を防止。 |
| **3. 永続性・互換性** | Obsidian, Logseq 等の Vault 直下に直接保存した際、タグやプロパティが即座に認識される互換性。 | 標準 YAML Frontmatter（配列タグ・日付）書式に厳密準拠。 |
| **4. テスト容易性 & 自律性** | エディタ双方向編集やファイル書き出しが自動テスト可能か。 | サニタイズ・パースの単体テストおよびエディタUIテストを Vitest で 100% ローカル完結。 |
