# Pre-Phase Verification Report (事前検証レポート)

各フェーズ着手前に実施する 4 軸（技術環境、UX、データ永続性、テスト自律性）の事前検証ログです。

---

## Phase 6: スキル・資格ステータス管理 & 資格推薦AI & 状態同期・接続テスト

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `ProfileSettingsView` でのプロファイル保存が `App.tsx` に即時反映されず `Mock モード` のままになる状態管理の不整合。 | `App.tsx` から `profile` および `saveProfile` を `ProfileSettingsView` に渡し、メモリ上の状態とストレージを単一ソースで同期。 |
| **2. UX・エッジケース** | APIキーが正しいか保存前に確認できない不安、資格・スキルの「取得済」と「学習中・目標」の混同。 | Gemini API 接続テストボタン（疎通確認）を新設。資格・スキルにステータス（取得済/学習中/目標）を追加し、タブ切り替えUIで直感的に登録。 |
| **3. 永続性・互換性** | 資格・スキル構造の拡張に伴う既存プロファイル（LocalStorage/Tauri FS）の後方互換性。 | 既存データに `status` がない場合はデフォルト値（`acquired` / `experienced`）を自動補完しマイグレーション。Markdown Frontmatter にも推奨資格プロパティを互換拡張。 |
| **4. テスト容易性 & 自律性** | API接続テストや資格アドバイス抽出ロジックが、APIキーなしのローカル環境でも 100% 単体テスト可能か。 | `MockAiProvider` にも `qualificationAdvice` モック生成を実装し、Vitest で完全ローカル自律テストを保証。 |

## Phase 5: 求人管理ダッシュボード & 複数比較 & 総合テスト

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | 大量案件保存時の検索・ソート処理の軽量化と、比較マトリクスの横スクロール表示。 | React メモ化フィルタリングと、グリッド/テーブルのレスポンシブ切り替え。 |
| **2. UX・エッジケース** | 0件時のガイド表示、ステータス変更時の即時永続化、比較対象（最大3件）の選択上限制御。 | ステータス更新フック (`updateJobStatus`) と選択バッジ・比較モーダル/パネル。 |
| **3. 永続性・互換性** | ステータス変更が Markdown メタデータおよびストレージの両方で整合性を保つこと。 | `storageAdapter.saveJob` でメタデータと Frontmatter を同期更新。 |
| **4. テスト容易性 & 自律性** | 検索・フィルタ・ソート・比較ロジックが自動テスト可能か。 | フィルタ・比較ロジックの単体テストおよびダッシュボード UI テストを Vitest で自動化。 |

## Phase 4: Markdown生成 & リッチプレビュー & Vault保存

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Frontmatter (YAML) を react-markdown で綺麗に表示・分離する必要性。 | `remark-frontmatter` を適用し、YAML と Markdown 本文を視覚的に整理してレンダリング。 |
| **2. UX・エッジケース** | 企業名・職種に OS 禁止文字 (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`) が含まれるリスク。 | `getStandardMarkdownFilename` で厳格サニタイズを実施し、不正ファイル名による保存失敗を防止。 |
| **3. 永続性・互換性** | Obsidian, Logseq 等の Vault 直下に直接保存した際、タグやプロパティが即座に認識される互換性。 | 標準 YAML Frontmatter（配列タグ・日付）書式に厳密準拠。 |
| **4. テスト容易性 & 自律性** | エディタ双方向編集やファイル書き出しが自動テスト可能か。 | サニタイズ・パースの単体テストおよびエディタUIテストを Vitest で 100% ローカル完結。 |
