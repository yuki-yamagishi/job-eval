# ADR-0004: 動的重み付けプロファイル (Dynamic Weighting Profile) および高速再計算エンジンの採用

- **ステータス**: **Accepted**
- **決定日**: 2026-08-30
- **関連Issue**: [#1](https://github.com/yuki-yamagishi/job-eval/issues/1)
- **関連ADR**: [ADR-0001](0001-four-axis-scoring-engine.md) (多軸求人適合度スコアリングエンジン)

---

## 1. 背景と課題 (Context & Problem Statement)
ADR-0001 において、4軸（スキル40% / 条件30% / 成長20% / 環境10%）の決定論的重み付けスコアリングエンジンを採用した。
しかし、この固定配分は「現在の実務経験・即戦力スキルを最重要視する転職活動」に特化しており、以下の多様な求職者ペルソナにおいて適切な適合度判定が得られない課題が生じていた：
1. **リスキリング・挑戦志向**: 現在のスキル一致度は低くても、得られる技術（成長性）や教育体制・会社のカルチャーを最優先したい。
2. **ワークライフバランス・社風重視**: スキル要件よりも労働環境健全性やチームカルチャーとの親和性を最重要視したい。
3. **待遇最優先**: 年収レンジやリモート条件の合致を最優先したい。
4. **多角的シミュレーション**: 同一求人リストを「リスキリング視点」や「即戦力視点」など異なる評価軸で比較検討したい。

## 2. 検討された選択肢 (Considered Options)
1. **選択肢 1: 重み変更のたびに LLM (Gemini API) を再実行して全文再解析する**
   - ✖ 課題: API コスト（トークン消費）の増大、通信遅延（数秒〜十数秒）、同一求人での再現性の低下。
2. **選択肢 2: クライアントサイドでの動的重み付け決定論的再計算エンジン (Dynamic Weighting Engine)**
   - 各求人に保存済みの4軸スコア内訳（`scoreBreakdown`: 各軸 0〜100%）を入力とし、ユーザープロファイルで定義された重み（%）に基づいてミリ秒単位で再計算。
   - プロンプトにもユーザーの志向（プリセット名・重点方針）を注入して定性分析の質も向上。

## 3. 決定内容と理由 (Decision Outcome & Rationale)
- **採用**: **選択肢 2（クライアントサイド動的重み付け決定論的再計算エンジン）**
- **理由**:
  1. **ゼロコスト・ミリ秒単位の即時性**: 各求人にはすでに `scoreBreakdown`（0〜100%）が保持されているため、純粋関数 `recalculateScoreWithWeights` により、LLM API を呼び出すことなく瞬時に全求人または選択中求人のスコア・判定ランク（S/A/B/C）を再計算できる。
  2. **ADR-0001 との完全整合**: スコア計算が決定論的純粋関数であるため、何度計算しても同じ入力に対して同じスコアが出力される完全な再現性を維持。
  3. **UX の飛躍的向上**: プレビュー画面やダッシュボードで、評価視点（🎯標準 / 🚀リスキリング重視 / 🌿カルチャー重視など）のピルをクリックするだけで、リアルタイムにスコアとソート順が切り替わる直感的なシミュレーション体験を実現。

## 4. プリセット定義とデータ構造

```typescript
export interface ScoringWeights {
  skill: number;        // スキル合致度 (%)
  condition: number;    // 希望条件合致度 (%)
  growth: number;       // キャリア成長性 (%)
  environment: number;  // 労働環境・カルチャー (%)
} // 合計 100%

export type ScoringPresetKey = "standard" | "reskilling" | "wlb_culture" | "salary_first" | "custom";
```

### 標準プリセット一覧:
- **標準バランス型 (`standard`)**: 40 / 30 / 20 / 10 % (デフォルト)
- **リスキリング・成長重視 (`reskilling`)**: 10 / 20 / 45 / 25 %
- **カルチャー・環境重視 (`wlb_culture`)**: 20 / 30 / 10 / 40 %
- **待遇・条件最優先 (`salary_first`)**: 25 / 50 / 15 / 10 %
- **カスタム配分 (`custom`)**: ユーザーがスライダー等で自由設定

## 5. トレードオフと影響 (Consequences & Trade-offs)
### メリット
- 多様なキャリア志向（未経験分野へのリスキリング挑戦・カルチャー重視など）への柔軟な対応。
- API 呼び出しなしでのリアルタイムシミュレーション体験。
- 保存済み求人データおよび Markdown Frontmatter の整合性をワンクリックで一括更新可能。
### 制約・考慮事項
- 重みの合計が必ず 100% になるよう UI 側でバリデーションと自動バランサーを提供する必要がある。
