# ADR-0009: Cloudflare D1 サーバーレスSQLとWeb Crypto E2EE暗号化による常時非同期クロスデバイス同期の採用

- **ステータス**: Accepted
- **決定日**: 2026-09-03
- **決定者**: JobEval 開発チーム
- **関連Issue**: [Issue #18](https://github.com/yuki-yamagishi/job-eval/issues/18)

---

## 1. 背景と課題 (Context & Problem Statement)

1. **P2P 同期の同時起動制約**:
   - 既存の P2P / WebSocket リレー同期（ADR-0008）は、PC と スマホが「同時に開いている瞬間」にのみデータを直接やり取りする設計であったため、PC を閉じた後にスマホから開いてもデータが取得できない非同期利用の課題があった。
2. **Local-First とゼロコスト・プライバシーの堅持**:
   - 外部データベースにデータを保存する場合でも、求人内容や希望年収・職歴などの個人情報が平文でサーバーに残るリスクを排除し、完全なプライバシー（Zero-Knowledge）を保証する必要がある。

---

## 2. 検討された選択肢 (Considered Options)

### 選択肢 1: 外部マネージド BaaS（Firebase / Supabase）への保存
- **メリット**: 認証・リアルタイムリスナーが標準装備。
- **デメリット**: ユーザーごとのアカウント作成が必要、無料枠の管理や外部プロジェクト依存が発生。

### 選択肢 2: Cloudflare D1 ＋ クライアント側 E2EE 暗号化（AES-GCM-256）
- **メリット**:
  - **完全無料（1日10万回書き込み・500万行読み取り無料）** で、個人利用〜中規模利用まで運用コストが完全 0 円。
  - **Zero-Knowledge プライバシー**: クライアント（ブラウザ）側で AES-GCM-256 暗号化してから D1 に送信するため、DB には暗号文しか残らず、開発者や Cloudflare 側でも個人情報を 1 文字も読めない。
  - **2 テーブル構成による超高速差分同期**: 変更のあった求人だけをミリ秒で同期可能。
  - **アカウント登録不要**: ルームコード（`JE-XXXX-XXXX`）から暗号化鍵を自動導出するため、ユーザー登録なしでワンタッチ同期。

---

## 3. 決定内容と理由 (Decision Outcome & Rationale)

### 採用: **選択肢 2（Cloudflare D1 ＋ Web Crypto E2EE 2テーブル構成 ＋ Local-First 楽観的UI）**

### 決定理由:
1. **真の非同期クロスデバイス体験**:
   - PC で求人を分析・保存しておけば、PC の電源を切った後でもスマホを開くだけで最新データが自動復元・閲覧可能。
2. **Local-First 楽観的UI**:
   - 画面操作は 0ms でローカルストレージに即時反映し、D1 同期はバックグラウンド非同期で実行するため、電波が悪い場所でもアプリが一切もたつかない。
3. **完全な拡張性（Schema Flexibility）**:
   - D1 のカラムには暗号化された JSON ドキュメントが格納されるため、将来「STAR法職務経歴」や新機能を追加しても SQL スキーマ変更なしでそのまま同期可能。

---

## 4. トレードオフと影響 (Consequences & Trade-offs)

### メリット (Positive Impact)
- PC ↔ スマホ間で、端末の起動状態に関係なくいつでもシームレスにデータが同期される。
- 暗号化キーは端末内でのみ管理され、データベース漏洩時でも情報漏洩リスクがゼロ。

### デメリット・制約 (Negative Impact / Limitations)
- ルームコードを紛失した場合、クラウド上の暗号化データを復号することはできない（ローカルストレージのデータは維持される）。
