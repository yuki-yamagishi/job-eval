# ADR-0001: 40/30/20/10% 多軸求人適合度スコアリングエンジンの採用

- **ステータス**: **Accepted**
- **決定日**: 2026-08-30
- **決定者**: JobEval 開発チーム

---

## 1. 背景と課題 (Context & Problem Statement)
従来の求人マッチングやプロンプト生成では、LLM に「総合スコア（0〜100点）」を直接出力させることが多く、評価基準が曖昧でプロンプト実行ごとにブレが生じる問題（ハルシネーション・再現性の欠如）があった。
また、スキル要件、年収・勤務地条件、キャリア成長性、社風マッチの各要素がどのように合算されたかがブラックボックス化し、ユーザーが「なぜこの点数なのか」を納得できない課題があった。

## 2. 検討された選択肢 (Considered Options)
1. **選択肢 1: LLM 単体直接採点（プロンプトで 0〜100 点を一発出力）**
2. **選択肢 2: 多軸重み付けハイブリッドスコアリングエンジン（40/30/20/10%）**
   - スキル・経験一致度: **40%** (Must要件 25% + Want要件 15%)
   - 希望条件合致度（年収・勤務地・リモート等）: **30%**
   - キャリア成長・挑戦機会: **20%**
   - 企業カルチャー・働き方適合: **10%**
   - NG条件（フル出社強制・夜勤等）: **自動 0 点 / 除外フラグ**

## 3. 決定内容と理由 (Decision Outcome & Rationale)
- **採用**: **選択肢 2（40/30/20/10% 多軸重み付けスコアリング）**
- **理由**:
  1. 各軸の小計（40, 30, 20, 10点満点）および Must/Want 要件のブレイクダウンが完全に透明化され、ユーザーが客観的に判断できる。
  2. スコア計算ロジックを `src/core/scoring/` 内の純粋関数として実装することで、LLM からは各項目の評価フラグ・数値のみを JSON Schema で受け取り、合計計算はクライアントの決定論的ロジックで行うため再現性が 100% 担保される。
  3. NG 条件による即時除外（0点化）をルールベースで厳格に適用可能。

## 4. トレードオフと影響 (Consequences & Trade-offs)
### メリット
- スコア算出の透明性・再現性・説明可能性の最大化。
- 純粋 TypeScript ロジックとして Vitest で 100% 単体テスト可能。
### 制約
- LLM に対して各軸の評価項目を構造化 JSON（JSON Schema）で出力させるプロンプト設計が必要。
