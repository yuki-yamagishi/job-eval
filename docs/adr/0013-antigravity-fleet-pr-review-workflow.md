# ADR-0013: Antigravity IDE Fleet 主導の最上位モデル PR レビュー＆修正・人間承認マージワークフローへの刷新

- **ステータス**: 採用 (Accepted)
- **更新日**: 2026-09-05
- **関連 Issue**: #38
- **置き換え対象**: ADR-0012 (GitHub Actions ＋ Gemini API による自動 AI PR レビューボット) を **Superseded**

---

## 1. コンテキストと課題 (Context & Problems)

ADR-0012 において、GitHub Actions ワークフロー（`ai-pr-reviewer.yml`）をトリガーとする AI レビューボットを試験導入しました。しかし、実際の運用を通じて以下の 5 つの深刻な構造的課題が浮き彫りとなりました：

1. **モデル性能の妥協 (Flash-Lite への劣化)**:
   - Google AI Pro プランでは、最上位モデル（`gemini-3.8-flash` 等）の RPD（日次リクエスト枠）が 20〜50 回/日と厳しく、GitHub Actions で自動実行すると即座に枯渇するリスクがあったため、軽量な `gemini-3.5-flash-lite` に妥協せざるを得なかった。
2. **外部 API の不安定性と CI ブロックリスク**:
   - Google 側の一時的な過負荷（503 UNAVAILABLE スパイク）やクォータ制限により、CI パイプラインが赤くブロックされるリスクが常に存在していた。
3. **実行待ち時間（待機ラグ）**:
   - GitHub Actions のコンテナ起動＋実行により、PR 発行ごとに毎回 1〜2 分の不要な待機時間が発生していた。
4. **レビュー即マージ問題（レビュー指摘の形骸化）**:
   - PR 起票直後にエージェントが自動でマージを行ってしまい、せっかく出力された指摘（`[must]`, `[should]` 等）を反映・修正するプロセスがスキップされていた。
5. **クラウド上での自動修正の破綻リスク**:
   - クラウド（Actions）上で自動修正まで完結させようとすると、クォータ消費が倍増し、型エラー等の自己修復が困難で壊れたコミットが作られる危険があった。

---

## 2. 決定事項 (Decision)

### ① GitHub Actions レビューワークフローの完全廃止（負債根絶）
- `.github/workflows/ai-pr-reviewer.yml` を完全削除し、API クォータ消費、モデル妥協、CI ブロックリスクなどの負債を根絶する。
- 既存の CI パイプライン（`.github/workflows/ci.yml`）は、純粋な品質ゲート（シークレット検査、ドキュメント検査、型検査、テスト、ビルド）のみとして健全・シンプルに保つ。

### ② Antigravity IDE Fleet（独立サブエージェント）による最上位モデルレビュー
- プルリクエスト（PR）起票後、メインの実装エージェントとは**思考コンテキストを完全に切り離した Fleet（独立サブエージェント）**を起動する。
- 実装者バイアスを排除し、`git diff` および `AGENTS.md` 規約のみをインプットとして、**Antigravity IDE の最上位モデル（Gemini 3.8 Flash）** で客観的第三者レビューを実施する。
- 指摘には重要度接頭辞（`[must]`, `[should]`, `[imo]`, `[nits]`, `[ask]`）を付与し、総合判定として `[LGTM]` または `[要修正]` を明記する。

### ③ GitHub PR への公式コメント記録（永続アーカイブ）
- Fleet はレビュー完了後、GitHub CLI（`gh pr comment <PR番号> --body "..."`）を実行し、**GitHub PR の Web UI スレッドに公式コメントとして永続記録**する。これにより、将来の監査や保守履歴としても完全に保全される。

### ④ 手元での迅速な自己修復コミット
- レビュー結果に `[must]` や `[should]` の指摘がある場合、メインエージェントが手元（Antigravity IDE）で迅速に修正。
- `npm.cmd run check`（全品質ゲート 100% PASS）を確認した上で、PR ブランチに追加コミット＆プッシュする。

### ⑤ 自動マージの厳禁と人間承認プロセスの確立
- **PR 起票後は自動マージを厳禁とし、PR は OPEN 状態を維持する**。
- レビュー指摘の解消と総合判定 `[LGTM]` を確認した上で、**人間（ユーザー）の明示的な指示または承認を得てからのみマージを実行する**。

---

## 3. 期待される効果と帰結 (Consequences)

### メリット (Positive)
- **クォータ制約ゼロ ＆ 最上位モデル使い放題**:
  - 個人 API キーの RPD 上限（20〜50回/日）に縛られることなく、Gemini 3.8 Flash の深い洞察力・推論力を 100% 活用できる。
- **圧倒的な自己修復力**:
  - プロジェクト全ファイル、型定義、ADR、Git 履歴、テスト実行エンジンを手元でフル活用できるため、指摘事項の修正が迅速かつ安全に行える。
- **CI 待ち時間ゼロ ＆ 安定稼働**:
  - GitHub Actions のコンテナ起動待ちや外部 API 503 による CI 赤ブロックがゼロになる。
- **ガバナンスと安全性の確立**:
  - レビュー即マージによる指摘の形骸化を根絶し、人間（ユーザー）の承認を経てマージされる確実なリリース統制が実現する。
