# ADR-0012: GitHub Actions ＋ Gemini API による自動 AI PR レビューボットの採用

## ステータス
**Superseded** (by [ADR-0013](file:///docs/adr/0013-antigravity-fleet-pr-review-workflow.md), 2026-09-05)

## 文脈 (Context)
JobEval リポジトリでは、AI エージェントが Issue 起票・ブランチ作成・コード実装・テスト作成・PR 発行までの一連のワークフローを自律的に遂行している。
しかし、実装を行ったエージェント自身が自己完結して PR を発行すると、以下のような懸念・課題が存在していた：
1. **実装者バイアスによるエッジケースの見落とし**: 実装エージェントは正常系シナリオや指定された要件に焦点を当てる傾向があり、データが空の場合や未初期化状態、型外の値が渡された際の耐久性、例外ハンドリングの漏れが見落とされるリスクがある。
2. **保守履歴としてのレビュー指摘の欠落**: 実装のどこがリスクで、どのような考慮に基づいて書かれたのか、または将来どんな点に注意して改修すべきかという知見（保守メモ）が PR 上に残りにくい。
3. **継続的なアーキテクチャ規約遵守の検証**: `AGENTS.md` に規定された「コアロジックの不可侵」「既存テストの弱体化禁止」「完全日本語ドキュメント標準化」等の重要規約が、機械的なテストだけでなく設計レビューの観点からも常時ダブルチェックされる仕組みが求められていた。

## 決定事項 (Decision)
プルリクエストが発行・更新（`pull_request: [opened, synchronize, reopened]`）された際に、GitHub Actions 上で独立した AI レビュアーを実行し、Gemini API を用いてコード差分と設計規約を多角的に検証して PR コメントを残す **「自動 AI PR レビューボット」** を導入する。

### 1. 独立したレビュアーペルソナとレビュー観点
AI レビュアーには以下のシニアテックリード・セキュリティエンジニアとしての役割を与え、以下の 4 つの観点に特化してレビューコメントを自動生成させる：
1. 🎯 **概要・変更インパクト評価**: 変更の意図、影響範囲、依存関係への影響。
2. 🛡️ **エッジケース & 潜在的リスク**: 空文字・未定義値・境界値・非同期レースコンディション・エラーハンドリングの漏れ。
3. 💡 **保守性 & コード品質の改善提案**: 命名、可読性、型安全性、リファクタリング推奨点。
4. 📋 **AGENTS.md / アーキテクチャ整合性チェック**: クリーンアーキテクチャ層の遵守、テスト弱体化の有無、日本語ドキュメント標準化。

### 2. 技術構成 & 運用プロトコル
- **トリガー**: GitHub Actions ワークフロー `.github/workflows/ai-pr-reviewer.yml`
- **実行スクリプト**: `scripts/aiPrReviewer.js` (Node.js ESM)
- **AI モデル**: Google Gemini 2.5 Flash（または設定されたモデル）
- **GitHub PR コメント投稿**: `gh pr comment` CLI または GitHub REST API（`GITHUB_TOKEN` 使用）
- **Graceful Skip 機構**: リポジトリの Secret `GEMINI_API_KEY` が設定されていない場合や、Fork からの PR 等でシークレットアクセスが制限されている場合は、CI 全体を失敗（Red）とせず、スキップ警告をログに出力して正常終了（Green）する。

## 結果・影響 (Consequences)

### ポジティブな影響
- **客観的品質ゲートの強化**: 実装者とは別の AI 視点から自動的に多角的レビューが行われ、潜在的なバグやエッジケースが早期に顕在化する。
- **保守メモの蓄積**: PR のコメントスレッドにレビュー指摘と注意点が恒久的にアーカイブされ、将来の保守開発時に「なぜこの実装になったのか」「何に気をつけるべきか」が即座に確認可能になる。
- **開発サイクルの加速**: 人間が手動で詳細なコード差分を追う負担が激減し、AI が指摘したエッジケースの修正確認に集中できる。

### トレードオフ・留意点
- **Gemini API クォータとコスト**: PR の更新ごと（`synchronize`）に API リクエストが発生するため、過剰な差分がある場合は diff を適切に要約・トリミングし、トークン消費とコストを抑制する。
- **CI 実行時間**: API 呼び出しに数秒〜十数秒要するが、非同期ジョブとしてバックグラウンドで完了するため、開発体験を阻害しない。
