## Phase 6: スキル・資格ステータス管理 & 資格推薦AI & 状態同期・接続テスト

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | `ProfileSettingsView` でのプロファイル保存が `App.tsx` に即時反映されず `Mock モード` のままになる状態管理の不整合。 | `App.tsx` から `profile` および `saveProfile` を `ProfileSettingsView` に渡し、メモリ上の状態とストレージを単一ソースで同期。 |
| **2. UX・エッジケース** | APIキーが正しいか保存前に確認できない不安、資格・スキルの「取得済」と「学習中・目標」の混同。 | Gemini API 接続テストボタン（疎通確認）を新設。資格・スキルにステータス（取得済/学習中/目標）を追加し、タブ切り替えUIで直感的に登録。 |
| **3. 永続性・互換性** | 資格・スキル構造の拡張に伴う既存プロファイル（LocalStorage/Tauri FS）の後方互換性。 | 既存データに `status` がない場合はデフォルト値（`acquired` / `experienced`）を自動補完しマイグレーション。Markdown Frontmatter にも推奨資格プロパティを互換拡張。 |
| **4. テスト容易性 & 自律性** | API接続テストや資格アドバイス抽出ロジックが、APIキーなしのローカル環境でも 100% 単体テスト可能か。 | `MockAiProvider` にも `qualificationAdvice` モック生成を実装し、Vitest で完全ローカル自律テストを保証。 |
