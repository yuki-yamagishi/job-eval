## Phase 9: キャリア展望の常設深掘り・再生成とプロンプト最適化

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | 初回一括生成のレスポンス速度（3秒台）を犠牲にせず、専用プロンプトによる詳細な深掘り分析を提供すること。 | 初回一括解析時はスマートな要約版を高速出力し、プレビュー画面右上に「🔄 AIでキャリア展望を再生成・深掘り」ボタンを常設配置。専用プロンプト（`buildCareerTrajectoryPrompt`）で高密度・具体的な分析結果へ即時アップグレード可能にする。 |
| **2. UX・エッジケース** | 展望がすでに存在する場合でも、再生成ボタンを押した際にローディング状態を表示し、スムーズに最新結果へ差し替わること。 | `isGeneratingTrajectory` ローディング状態とスピナーを表示。再生成完了時は Markdown ドキュメントも自動同期更新しローカルストレージへ即時反映。 |
| **3. 永続性・互換性** | 再生成された `careerTrajectory` がローカル保存データおよびエクスポート用 Markdown に欠落なく永続化されること。 | `generateJobMarkdown` で新展望を反映した Markdown を自動再生成し、`saveJob` で自動保存。 |
| **4. テスト容易性 & 自律性** | 再生成トリガー、UI ローディング挙動、専用プロンプトのテストが Vitest で自律実行可能か。 | `tests/features/PreviewPane.test.tsx` に再生成ボタンの押下・コールバック呼び出しテストを追加。 |
