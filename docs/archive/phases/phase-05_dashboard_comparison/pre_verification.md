## Phase 5: 求人管理ダッシュボード & 複数比較 & 総合テスト

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | 大量案件保存時の検索・ソート処理の軽量化と、比較マトリクスの横スクロール表示。 | React メモ化フィルタリングと、グリッド/テーブルのレスポンシブ切り替え。 |
| **2. UX・エッジケース** | 0件時のガイド表示、ステータス変更時の即時永続化、比較対象（最大3件）の選択上限制御。 | ステータス更新フック (`updateJobStatus`) と選択バッジ・比較モーダル/パネル。 |
| **3. 永続性・互換性** | ステータス変更が Markdown メタデータおよびストレージの両方で整合性を保つこと。 | `storageAdapter.saveJob` でメタデータと Frontmatter を同期更新。 |
| **4. テスト容易性 & 自律性** | 検索・フィルタ・ソート・比較ロジックが自動テスト可能か。 | フィルタ・比較ロジックの単体テストおよびダッシュボード UI テストを Vitest で自動化。 |
