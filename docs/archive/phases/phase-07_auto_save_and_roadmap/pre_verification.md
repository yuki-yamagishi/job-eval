## Phase 7: 自動ローカル保存・再表示・AI再評価・MDインポート・横並び比較 & 転職ロードマップ画面

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | Markdown (`.md`) インポート時の YAML Frontmatter パースと、AIへのフィードバック付き再評価プロンプトの設計。 | 既存の `parseJobMarkdown` を拡張してドラッグ＆ドロップ/ファイル選択に対応。AI 再評価用プロンプトビルダー（前回評価＋ユーザーフィードバック）を新設。 |
| **2. UX・エッジケース** | 解析完了時に手動保存を押さなくても自動でローカル保存される安心感。保存済み案件のワンクリック再表示。複数案件の横並び比較。選考状況（応募検討中/面接/見送り等）と不足資格を俯瞰するロードマップ画面。 | ① 解析完了時の自動ローカルストレージ保存（ドラフト同期）、② ダッシュボードからの1クリック再プレビュー復元、③ プレビューペイン内の「💡 フィードバックして再評価」フォーム、④ ドキュメントインポートモーダル、⑤ 横並び比較マトリクス、⑥ 新ナビゲーション「ロードマップ」タブの新設。 |
| **3. 永続性・互換性** | ユーザーフィードバック履歴や更新日時が Markdown Frontmatter およびローカルストレージの両方で正しく永続化されること。 | `JobAnalysisResult` に `feedbackHistory?: Array<{ date: string; feedback: string; scoreDelta: number }>` を追加し、既存データとの完全互換を維持。 |
| **4. テスト容易性 & 自律性** | Markdown インポート、AI 再評価ロジック、ロードマップ集計ロジックが、APIキーなしのローカル環境でも 100% 単体テスト可能か。 | `MockAiProvider` に再評価ロジックを組み込み、Vitest でインポートパース・フィードバック再評価・ロードマップ集計を 100% 自動テスト化。 |
