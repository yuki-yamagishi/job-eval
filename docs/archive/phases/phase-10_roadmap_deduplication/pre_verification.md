## Phase 10: 転職ロードマップのデータ整合性・名寄せ重複排除・出所会社別明記 & 更新機能新設

| 検証軸 | 検出事項・考慮点 | 実装・設計での解決策 |
| :--- | :--- | :--- |
| **1. 技術・環境** | 表記ゆれ（例: `AWS SAA`, `AWS Certified Solutions Architect - Associate` 等）による資格の重複集計、および同一企業による重複カウントの排除。 | 主要資格の正規化マッピング辞書を導入し、同一求人内・同一企業内での重複カウントを Set で厳密排除。 |
| **2. UX・エッジケース** | 「どの会社が必須として求めているのか」「どの会社がアピール推奨と言っているのか」が混同せず一目でわかること。ロードマップ手動更新ボタンの設置。 | 各資格カードに「🏢 企業ごとの指定文脈（必須指定 / 経験補強の推奨）」を企業名バッジとともに個別明記。ヘッダー右上に「🔄 データを再集計・更新」ボタンを新設。 |
| **3. 永続性・互換性** | 保存求人データの構造（`qualificationAdvice`, `careerTrajectory`）に変更を加えることなく、ロードマップ表示ロジック側で柔軟かつ高精度に集計すること。 | 既存の `JobAnalysisResult` 型との完全互換を維持し、集計アルゴリズム（`useMemo`）を安全に強化。 |
| **4. テスト容易性 & 自律性** | 表記ゆれ名寄せ、企業別文脈分類、手動更新ボタンの押下挙動が Vitest で 100% 自動テスト可能か。 | `tests/features/CareerRoadmapView.test.tsx` に名寄せ・企業別明記・更新ボタンの単体UIテストを追加。 |
